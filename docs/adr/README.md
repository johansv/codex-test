# Architecture Decision Records

This directory stores ADRs generated alongside requirements. Drafts are created
automatically when prompts mention architectural changes. Review guidance:

1. **Proposed** – initial draft created by automation. Fill in Context, Decision,
   and Consequences before merging related code.
2. **Accepted** – once implementation lands and aligns with the decision, update
   the status to *Accepted* and link to requirement IDs, commits, and tests.
3. **Superseded** – when a follow-up ADR replaces the decision, mark the prior
   record as *Superseded* and cross-reference the successor.

Keep filenames in the format `adr-YYYYMMDD-<slug>.md` and ensure every ADR cites
at least one requirement ID so traceability stays intact.
